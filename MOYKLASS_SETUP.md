# Инструкция для менеджера: «Мой Класс» и Telegram-приложение

Понадобится доступ к настройкам CRM. Сервер настраивает разработчик.

## 1. Создайте поля ученика

1. Откройте **Настройки → Признаки клиента** (название раздела может быть «Признаки ученика»).
2. Создайте признаки именно для **ученика**. Для каждого укажите название и тип из таблицы, затем сохраните.
3. Если CRM просит **алиас** или **код**, скопируйте значение из последнего столбца. Если такой настройки нет, оставьте автоматически созданное значение и сообщите разработчику.

| Название | Тип | Варианты / начальное значение | Алиас, если запрашивается |
| --- | --- | --- | --- |
| Бот — Доступ | Да/Нет | Начальное значение «Нет» | `bot__dostup` |
| Бот — Доступ до | Текст | Пусто | `bot__dostup_do` |
| Бот — Тип доступа | Список, один вариант | «Пробный», «Платный» | `bot__tip_dostupa` |
| Бот — Предметы | Список, один вариант | «Математика», «Русский язык», «Химия», «Физика», «Английский язык» | `bot__predmety` |
| Бот — Последний вход | Текст | Пусто | `bot__posledniy_vhod` |
| Бот — Telegram ID | Текст | Пусто | `bot__telegram_id` |
| Бот — ID пользователя | Текст | Пусто | `bot__id_polzovatelya` |
| Бот — Последняя синхронизация | Текст | Пусто | `bot__poslednyaya_sinhronizaciya` |
| Бот — Ошибка синхронизации | Текст | Пусто | `bot__oshibka_sinhronizacii` |

Поле **«Бот — Доступ до»** создайте текстовым, даже если CRM предлагает тип «Дата»: приложению иногда нужно точное время. В поле **«Бот — Предметы»** выбирается один предмет. Существующее поле «Предмет» не подходит: оно относится к занятиям.

## 2. Проверьте теги

Теги **«Пробный период»**, **«Подписка есть»**, **«Бот оплачен»**, **«Бот не оплачен»** уже созданы. Проверьте, что они видны в CRM. Не создавайте дубликаты и не меняйте эти теги вручную для выдачи доступа: приложение будет обновлять их после подключения.

## 3. Включите уведомление об изменении ученика

Этот шаг выполните, когда разработчик передаст готовый адрес вебхука.

1. Откройте **Настройки → API и webhooks**, создайте вебхук, вставьте адрес без изменений и сохраните.
2. Откройте **Настройки → Сценарии**. Создайте сценарий с событием **«Информация об ученике изменилась»** и действием **«Отправить вебхук»**. Выберите сохранённый вебхук.
3. Если CRM предлагает выбрать конкретные изменения, отметьте поля «Бот — Доступ», «Бот — Доступ до», «Бот — Тип доступа» и «Бот — Предметы». Сохраните сценарий.

Адрес вебхука передавайте только сотруднику, который настраивает CRM.

## 4. Выдавайте доступ через карточку ученика

Сначала ученик открывает Telegram-приложение. Затем администратор приложения связывает его аккаунт с **конкретной карточкой ученика** в CRM. Передайте администратору ID карточки. Не выбирайте карточку только по имени или телефону.

После подтверждения связи откройте карточку и заполните:

1. **«Бот — Доступ»**: «Да».
2. **«Бот — Тип доступа»**: «Пробный» или «Платный».
3. **«Бот — Доступ до»**: дата вида `ГГГГ-ММ-ДД`, например `2026-10-31`. Доступ действует до конца этого дня по Минску. Для точного времени можно указать `2026-10-31T18:00:00+03:00`.
4. **«Бот — Предметы»**: выберите предмет, к которому открываете доступ.
5. Сохраните карточку.

Для продления измените дату и сохраните карточку. Если доступ был выключен, снова установите «Да». Чтобы сразу закрыть доступ, установите «Нет» и сохраните.

Поля «Последний вход», «Telegram ID», «ID пользователя», «Последняя синхронизация» и «Ошибка синхронизации» заполняет приложение. Менеджеру их редактировать не нужно.

## 5. Проверьте результат

1. Выберите тестовую карточку и передайте её ID администратору приложения для связи с тестовым Telegram-аккаунтом.
2. Выдайте пробный доступ с одним предметом. Попросите тестового ученика открыть приложение и проверить предмет.
3. Выберите другой предмет и проверьте, что доступ переключился на него.
4. Отключите доступ и проверьте, что материалы больше не открываются.

**После создания полей передайте разработчику** скриншоты названий, типов и вариантов полей, а также ID тестовой карточки. Разработчик проверит связь и завершит подключение. Если тест не проходит, приложите скриншот четырёх полей доступа. API-ключ в переписку не отправляйте.
